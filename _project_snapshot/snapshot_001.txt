## СПРИНТ 7. Повторный аудит: надёжность под нагрузкой, безопасность, продакшен

Рекомендуемый порядок: 7.1–7.4 → 7.5, 7.7 → релиз 7.14 → остальное по продуктовым приоритетам.

### Приоритет 0 — дефекты, которые проявятся под нагрузкой или при сбое

### - [x] Таск 7.1. Короткие сессии БД в WebSocket (`fix/ws-short-lived-db-sessions`)

* Проблема: `src/api/websockets.py` берёт одну сессию БД на всё WS-соединение; первый запрос открывает транзакцию,
  которая не закрывается. Каждый подключённый игрок держит соединение пула в состоянии «idle in transaction» —
  при ~15 игроках (пул 5+10) остальные запросы к БД висят 30 с и падают.
* Сделать: отдельная короткая сессия на каждое действие; размер пула — в настройки.
* Готово: тест, что после действия нет открытой транзакции и соединение вернулось в пул.

### - [x] Таск 7.2. Изоляция ошибок в цикле таймаутов (`fix/timeouts-loop-isolation`)

* Проблема: `check_timeouts_loop` (`src/services/game_state.py`) обходит все партии в одном `try`; одна «битая»
  партия прерывает проход — флаги и отмены перестают срабатывать во всех партиях. Ошибка логируется без стека.
* Сделать: `try` на каждую партию, `logger.exception`, счётчик повторных сбоев.
* Решение: вместо карантина — растущая пауза (1 с → 30 с) для падающей партии; партия не удаляется из
  `active_games`, иначе временный сбой БД «потерял» бы все идущие партии.
* Готово: тест — партия с повреждённым состоянием не мешает флагу в соседней.

### - [x] Таск 7.3. Сверка партий, застрявших между Redis и БД (`fix/game-end-reconciliation`)

* Проблема: `claim_game_end` пишет `completed` в Redis, затем `finish_game` пишет в БД. Сбой между шагами — партия
  навсегда `in_progress` в БД, рейтинг не начислен.
* Сделать: фоновая сверка (и проход при старте), дозавершающая такие партии через идемпотентный `finish_game`.
* Готово: тест — сбой `finish_game` после claim исправляется на следующем проходе.
* Сделано: реестр `games:pending_finish` (добавляется в транзакции завершения, снимается после коммита в БД);
  лидер цикла таймаутов раз в 30 с (и сразу при старте) дозавершает партии старше 30 с и уведомляет игроков;
  партии `in_progress` в БД, потерявшие состояние в Redis, восстанавливаются; телеметрия ходов удаляется
  только после коммита.

### - [x] Таск 7.4. Неблокирующая постановка Celery-задач (`fix/async-task-dispatch`)

* Проблема: `analyze_game_task.delay()` — синхронный сетевой вызов в async-коде; при недоступном брокере
  подвешивает весь воркер (ходы, часы, все WS).
* Сделать: `asyncio.to_thread`, ограниченные повторы публикации и таймаут.
* Найдено попутно: задача была `@shared_task`, а API-процесс не импортировал `celery_app` — публикация шла
  в `amqp://localhost:5672` вместо Redis, фоновый анализ до воркера не доходил. При недоступном брокере
  бэкенд результатов переподключался ~64 с и ломался до перезапуска процесса.
* Сделано: `src/services/task_dispatch.py` (публикация в потоке, не ждётся, таймаут, пауза 30 с после сбоя);
  задача привязана к `celery_app`, `ignore_result=True`; короткие таймауты брокера. Сбой брокера: 1,2 с в
  фоновом потоке вместо 64 с блокировки event loop.

### - [x] Таск 7.5. Защита входа и регистрации (`fix/auth-hardening`)

  имя 3–30 символов, латиница или кириллица без смешения, цифры, `_`, `-`; колонка `username_key`
  (casefold, уникальный индекс, миграция `e5b7c9d1a2f3`) — у архивных игроков и ботов NULL; вход в любом
  регистре; запрет служебных имён, имён ботов и чемпионов; проверка пароля для несуществующего аккаунта
  (против перебора имён по времени ответа); фронтенд показывает ошибки валидации и 429.

### - [x] Таск 7.6. Жизненный цикл токенов (`feat/token-lifecycle`)

* `sub = user.id` и `token_version` у пользователя — отзыв токенов при смене пароля и «выйти везде».
* Убрать JWT из query-строки WebSocket (одноразовый тикет в Redis или токен первым сообщением).
* CSP; в перспективе httpOnly cookie + refresh-токен вместо `localStorage`.
* Сделано: JWT `{sub: id, ver: token_version}` (миграция `f6c8d0e2b3a4`), `POST /auth/logout-all`,
  `POST /auth/change-password` (отзывает старые токены, возвращает новый), отзыв закрывает открытые WebSocket
  на всех воркерах (событие `session_revoked`, код 1008); WebSocket подключается по одноразовому тикету
  `POST /auth/ws-ticket` (Redis, 30 с, GETDEL); кнопка «Выйти на всех устройствах». Старые токены после
  деплоя недействительны — пользователи один раз войдут заново.
* Осталось (перенесено в 7.11): CSP-заголовок на nginx (мета-тег сломал бы HMR Vite в разработке),
  httpOnly cookie + refresh-токен — отдельная задача, меняет весь клиент.

### - [x] Таск 7.7. Rate limit сообщений WebSocket (`fix/ws-message-rate-limit`)

* Лимиты по типам действий (чат, предложения ничьей и реванша, очередь) и ограничение размера сообщения.
* Сделано: лимиты на пользователя в Redis (общие для всех вкладок): ходы 60/10 с, чат 5/10 с, предложения
  6/мин, лобби 20/10 с, прочее 30/10 с; сообщение не длиннее 4096 символов; 30 отклонённых сообщений за 10 с
  закрывают соединение (1008); мусорный JSON больше не рвёт соединение; ничью можно предложить один раз за ход;
  отклонённый по лимиту ход возвращает клиенту актуальную позицию.

import asyncio
from logging.config import fileConfig

from alembic import context
from sqlalchemy import pool
from sqlalchemy.engine import Connection
from sqlalchemy.ext.asyncio import async_engine_from_config

# Импорт конфигурации и базовой модели
from src.core.config import settings
from src.models import Base

config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata


def run_migrations_offline() -> None:
    url = settings.async_database_url
    context.configure(
        url=url,
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
    )

    with context.begin_transaction():
        context.run_migrations()


def do_run_migrations(connection: Connection) -> None:
    context.configure(connection=connection, target_metadata=target_metadata)

    with context.begin_transaction():
        context.run_migrations()


async def run_async_migrations() -> None:
    configuration = config.get_section(config.config_ini_section, {})
    configuration["sqlalchemy.url"] = settings.async_database_url

    connectable = async_engine_from_config(
        configuration,
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )

    async with connectable.connect() as connection:
        await connection.run_sync(do_run_migrations)

    await connectable.dispose()


def run_migrations_online() -> None:
    asyncio.run(run_async_migrations())


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()

# game_id -> [lock, число запросов, ожидающих или держащих лок]. Запись удаляется, когда
# счётчик падает до нуля, поэтому словарь не растёт с каждой когда-либо анализированной партией.
_ANALYSIS_LOCKS: dict[int, list] = {}


@asynccontextmanager
async def _game_analysis_lock(game_id: int):
    entry = _ANALYSIS_LOCKS.setdefault(game_id, [asyncio.Lock(), 0])
    entry[1] += 1
    try:
        async with entry[0]:
            yield
    finally:
        entry[1] -= 1
        if entry[1] == 0:
            _ANALYSIS_LOCKS.pop(game_id, None)


def _engine_busy() -> HTTPException:

        detail="Движок сейчас занят, повторите запрос через несколько секунд",
        headers={"Retry-After": "5"},
    )

@router.post("/register", response_model=UserResponse, status_code=status.HTTP_201_CREATED)
async def register_user(user_in: UserCreate, request: Request, db: AsyncSession = Depends(get_db)):
    """
    Register a new user.
    """
    await enforce_rate_limit(
        "register", f"ip:{client_ip(request)}",
        settings.RATE_LIMIT_REGISTER_PER_IP, settings.RATE_LIMIT_REGISTER_WINDOW_S,
        "Слишком много регистраций с этого адреса, попробуйте позже",
    )

    if _is_reserved(user_in.username):
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="Это имя зарезервировано за историческим ботом или служебной страницей."
        )

    key = username_key(user_in.username)
    # username_key есть у аккаунтов с паролем; архивные игроки из PGN и боты его не имеют,
    # поэтому с ними сверяемся и по самому имени.
    result = await db.execute(select(User.id).where(or_(
        User.username_key == key,
        func.lower(User.username) == user_in.username.lower(),
    )))
    if result.first() is not None:
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail=DUPLICATE_USERNAME_DETAIL)

    new_user = User(
        username=user_in.username,
        username_key=key,
        hashed_password=get_password_hash(user_in.password),
    )
    db.add(new_user)
    try:
        await db.commit()
    except IntegrityError:
        # Параллельная регистрация того же имени (в другом регистре) — уникальный индекс в БД.
        await db.rollback()
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail=DUPLICATE_USERNAME_DETAIL) from None
    await db.refresh(new_user)

    return new_user


async def _find_login_user(db: AsyncSession, username: str) -> User | None:
    result = await db.execute(select(User).where(User.username == username))
    user = result.scalars().first()
    if user is None:
        # Вход в любом регистре: «misha» найдёт аккаунт «Misha».
        result = await db.execute(select(User).where(User.username_key == username_key(username)))
        user = result.scalars().first()
    return user


@router.post("/login")
async def login(
        request: Request,
        form_data: OAuth2PasswordRequestForm = Depends(),
        db: AsyncSession = Depends(get_db)
):
    """
    OAuth2 compatible token login, get an access token for future requests.

    Подбор пароля ограничен дважды: все попытки с одного IP (перебор по многим аккаунтам)
    и неудачные попытки на один аккаунт (перебор одного пароля с многих адресов).
    """
    await enforce_rate_limit(
        "login", f"ip:{client_ip(request)}",
        settings.RATE_LIMIT_LOGIN_PER_IP, settings.RATE_LIMIT_LOGIN_WINDOW_S,
        "Слишком много попыток входа, попробуйте через минуту",
    )
    account = f"account:{username_key(form_data.username)}"
    await ensure_below_limit(
        "login_failures", account,
        settings.RATE_LIMIT_LOGIN_FAILURES_PER_ACCOUNT, settings.RATE_LIMIT_LOGIN_FAILURES_WINDOW_S,
        "Слишком много неудачных попыток входа в этот аккаунт, попробуйте позже",
    )

    user = await _find_login_user(db, form_data.username)
    password_ok = verify_password(form_data.password, user.hashed_password if user else _DUMMY_PASSWORD_HASH)

    if user is None or not password_ok:
        await record_attempt("login_failures", account, settings.RATE_LIMIT_LOGIN_FAILURES_WINDOW_S)
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail=LOGIN_FAILED_DETAIL,
            headers={"WWW-Authenticate": "Bearer"},
        )

    access_token = create_user_token(user)

    return {
        "access_token": access_token,
        "token_type": "bearer"
    }

@router.post("/change-password")
async def change_password(
        payload: PasswordChange,
        current_user: User = Depends(get_current_user),
        db: AsyncSession = Depends(get_db),
):
    """
    Смена пароля. Все ранее выданные токены отзываются (на случай, если пароль меняют из-за
    утечки), а текущему клиенту возвращается новый токен, чтобы он остался в системе.

    await ensure_below_limit(

    await _revoke_all_tokens(db, current_user)
